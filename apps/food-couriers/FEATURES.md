# Production features

Generated by SymplrV3 for the **Expo** target.
Some features are active out of the box; others are wired utilities waiting for
your custom code (`src/custom/` — never overwritten). This file says which is which.

## Active out of the box

- **TanStack Query** — generated hooks per API operation (`src/gen/api/*`); QueryClientProvider mounted in App.tsx when APIs exist.
- **Theme** — `ThemeProvider` mounted; system scheme + persisted override, readable as `const { scheme, setMode } = useThemeMode()` from `src/gen/theme/ThemeProvider`. **One palette:** `theme/tokens.ts` carries the design's colours only, with no dark variant, and no generated screen reads the scheme — so switching it changes nothing until you add dark tokens and consume them from `src/custom/**`.
- **Tailwind (NativeWind)** — for code YOU write in `src/custom/**`: `<View className="p-md bg-primary rounded-lg">`. The scale IS the design's tokens (`tailwind.config.js` is regenerated from Figma), and one class per type token: `className="typography-body"`. Lengths are emitted in `vw`, so `p-md` scales exactly like the `s(16)` a generated screen uses — a literal pixel is still `p-[16px]`. Generated screens under `src/gen/**` deliberately keep style objects and are not scanned.
- **Session** — `src/gen/features/session.ts`. Call `setSession(access, refresh)` after login; the API client then sends `Authorization: Bearer …` automatically (see `src/custom/api-auth.ts`) and retries a 401 once through `refreshSession()` (fill in your refresh endpoint there).
- **Typed errors** — every API failure is an `AppError` (`src/gen/errors.ts`). Show one: `errorMessage(query.error)`.
- **Deep-link validation** — only real screens navigate (`src/gen/navigation/linking.ts`); unknown paths are rejected, and screens the design marks `requiresAuth` are refused to a signed-out session. **No screen is marked in this design**, so every screen is currently reachable by link without a session.
- **Force update** — `ForceUpdateGate` blocks when the installed version < `EXPO_PUBLIC_MIN_APP_VERSION` (set it in `.env`).
- **Validated env** — `env('KEY', fallback)` / `requireEnv('KEY')` from `src/gen/env.ts`.
- **Supply-chain** — `npm run audit`, `npm run check:secrets`, `.env` git-ignored, zero patch-package. Both scripts run on every push via `.github/workflows/ci.yml`; neither is a substitute for a real scanner on a repo holding live credentials. **Commit `package-lock.json` after your first install** — it is what makes two checkouts of the same commit resolve the same tree. The `^` ranges in package.json do not, and `.npmrc`'s `save-exact` only governs packages you add later; the versions the platform resolves for you (React, React Native and their peers) are already pinned exactly.
- **Build perf** — Metro tuned per target; Hermes on.
- **Latent web** — `npm run web` starts the web build (react-native-web).
